## What changed and why

Document viewer picture metadata labels (`.info-label` on the light `.picture-cards` strip) previously used hardcoded `#777`, which IBM Equal Access reports at **4.48:1** on white — below WCAG 2.1 SC 1.4.3 AA (IBM issue **716638997**). The strip already uses the scoped host token `--document-viewer-muted-on-light-surface` (#5c5f6b); this change **locks that contract in regression tests** under every compiled theme so the failure cannot return silently.

## JIRA ticket

[NXENG-812](https://hyland.atlassian.net/browse/NXENG-812)

## Acceptance criteria

1. **[from ticket]** Violation remediated on the affected UI without hiding the control in the manifest only — `.info-label` uses the light-strip muted host token, not theme surface-variant or `#777`.
2. **[from ticket]** IBM re-scan should no longer report issue **716638997** — contrast ≥ 4.5:1 on the picture-cards strip (verified in unit tests).
3. **[from ticket]** No regression to layout, keyboard use, or authentication — CSS-only comment + tests; no template or auth changes.

## Approach

| Candidate                        | Verdict                                                                                                                   |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Darken `.info-label` only        | Already done via `--document-viewer-muted-on-light-surface` (NXENG-801); this ticket adds NXENG-812 traceability + tests. |
| Use `mat-sys-on-surface-variant` | Rejected — fails AA on the fixed light strip in dark theme (same class of defect as NXENG-764/801).                       |
